# c3 — the reassociation opt-in, v0 (whole program, by declaration)

C3 of `plan-beat-c-one-core.md`: a declared permission to regroup float
arithmetic. The default stays strict and reproducible. Only `bend2/main.ts`
changed (+10 −2 lines). No change to `comp.ts` or `bend.ts`, no new syntax, no cap moved
(main.ts is at 7335 ttok against its 10000 cap; `bun gates/repo.ts` shows
PASS 56 / 56).

**Headline, stated plainly: the flag works, but it does not move the tensor
rows.** It hands clang the permission, and clang uses it wherever the emitted
loop has a shape it can vectorize (a 2.6x speedup on a plain fold, below).
The gemv/split dot loop does not have that shape, so the permission never
reaches it. The 6.7x the C twin gains from the same permission is still out of
Bend's reach, and the reason is the emitted loop shape, not the permission.

## Spelling

    BEND_REASSOC=1 bend prog.bend -o prog

Any non-empty value turns it on, the same convention as `BEND_NO_TELEMETRY`.
It applies when a binary is built (`-o` without `.c`/`.js`). An emitted
`.c`/`.js` file is unchanged, and so is a GPU program. On a `!` build the
host C gets the flags, but NVRTC/Metal do not.

## Semantics: exactly what clang is given

With the flag set, the cc line gains:

    -fassociative-math -fno-signed-zeros -fno-trapping-math

- `-fassociative-math` lets clang treat float `+`/`*` as associative, so it can
  split a chain `((a+b)+c)+d` into partial sums, vectorize them, and add the
  partials at the end. This is the permission the lane is about.
- `-fno-signed-zeros` and `-fno-trapping-math` are there because clang only
  applies reassociation when both are set. The cost: the sign of a zero result
  may change (`-0.0` may become `+0.0`), and FP exceptions are not preserved as
  observable. Bend exposes neither today.
- **Not given** (the rest of `-ffast-math`): `-ffinite-math-only`, which would
  let clang delete inf/NaN checks and silently break the bench's `nonfin` probe;
  `-freciprocal-math`; `-fapprox-func`; and the `crtfastmath.o` FTZ/DAZ startup
  that flushes denormals process-wide. **Contraction stays off**: the emitted
  `#pragma clang fp contract(off)` overrides the command line, so no FMA fusion
  happens and every multiply still rounds separately. Turning contraction on
  under the flag would mean editing the pragma in comp.ts, which is out of scope
  for a main.ts-only slice. It is the next knob to add, and is listed in the
  residuals.

What changes, by declaration: a float result may round differently from the
strict build, and in principle it may differ between thread counts and lanes,
because the regrouping depends on how clang vectorized each loop. JS lanes
never reassociate, so under the flag the C and JS answers may disagree. In
every run below, 1T and 16T agreed.

## With the flag: the tensor table

`bash receipts/c3_bench.sh` (the bench lock, medians of three, seconds).
**The load average was 9.81 / 13.50 / 9.18**: other sessions were busy, so the
absolute numbers are inflated. The ratios within each row are what to read.

    bench      C    C-RA   C-ff |  bend1T  RA-1T  RA-16T | RA checksum vs strict twin
    gemv   0.155   0.023  0.016 |  0.161   0.157  0.161  | same (1993981018)
    split  0.154   0.022  0.016 |  0.157   0.157  0.157  | same (1993981018)
    blocked 0.044  0.059  0.021 |  0.106   0.104  0.112  | differs: 2852855167 vs 1297551341

C-RA is the twin with the same three flags; C-ff is the plan's fast-math row
(`-march=native -ffast-math`).

- **gemv / split: no change.** The checksum under the flag is bit-identical to
  the strict build's, which confirms clang reassociated nothing. The reason,
  from `-Rpass-missed=loop-vectorize` on the emitted C: the dot loop is a
  `WL_SPIN` loop that calls a fallible step (`if (spin_3(...) == 0) return 0;`
  is an early exit) and loads through `blk_ptr` (`u32a*`). The vectorizer stops
  there ("cannot identify array bounds", "not beneficial") before float
  associativity ever comes up. That matches the earlier probe that found
  `blk_ptr` blocks the loads.
- **blocked: the permission is taken but gains nothing.** The checksum moves,
  and 1T and 16T agree on the new value, so the declared rounding change is
  real. The time holds (0.104 vs 0.106). The twin gets *slower* with RA alone
  (0.044 to 0.059), and needs `-march=native` on top to reach 0.021.
- **Where it does pay off:** a plain fold. See the worked example.

## Worked example: the permitted rounding difference

`receipts/c3_harmonic.bend` adds `1/1 + 1/2 + … + 1/10⁷` in F32, strictly left
to right:

    build                      bits         value         time
    strict  (C 1T, 16T, JS)    1098282364   15.403683     0.0077 s
    BEND_REASSOC=1 (1T, 16T)   1099286076   16.721794     0.0029 s   (2.6x)
    plain C, strict -O3        1098282364   (same bits as Bend strict)
    plain C, the 3 flags       1099286076   (same bits as Bend RA)
    true H(10⁷), in f64                      16.695311

In strict order, the F32 sum stalls near 15.40: once `1/i` is below half an ulp
of the running sum, each addition rounds to nothing. The reassociated build
keeps several interleaved partial sums, each small enough to still absorb its
terms, then adds them at the end. The result is different bits and a different
value, closer to the truth in this case (though reassociation does not promise
"more accurate", only "differently rounded"). That is the point of the flag:
this answer is only correct under the declaration. Bend under the flag matches
plain C under the same flags bit for bit, so the flag means exactly the clang
semantics listed above.

## Residuals

1. **The loop shape, not the permission, limits gemv.** For the gemv row to
   approach C-RA (6.7x), the emitted dot loop needs no fallible call inside the
   reduction and plain, non-atomic, bounded loads. That work belongs to the
   emitter/lowering (C2b's territory, and the `blk_ptr` finding). This flag is
   ready for it: once the loop can vectorize, `BEND_REASSOC=1` is the switch
   that allows the reduction to be split.
2. **Per-fragment granularity.** v0 applies to the whole program. The real C3
   is a source marker on a fragment, lowered to `#pragma clang fp
   reassociate(on)` around just that function in the emitted C (clang scopes it
   per block). That needs syntax in `bend.ts`, which is human-written, so it is
   a future slice, not this one.
3. **Contraction.** An opt-in for `contract(fast)` (FMA) is the other half of
   the fast-math row. It means editing the comp.ts pragma, which this
   main.ts-only slice left alone.
4. **`-march`** is C1's lane. The C-ff column shows that the fast-math row
   depends on it as much as on reassociation.
